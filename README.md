# 요기보 배송조회 (cdApi)

오프라인 매장 매니저가 **고객 이름으로 배송 진행상황을 조회**하는 사내 도구.
물류팀이 매일 올리는 출고내역 엑셀을 적재하고, 택배사 공식 조회 페이지로 연결한다.

- 택배사 API 는 쓰지 않는다. 운송장번호를 URL 에 실어 택배사 페이지를 새 탭으로 연다.
  (경동택배는 공식 API 가 없고, 롯데 포털은 접수·출력용이라 조회 API 유무가 불명)
- 실제 배송 상태는 버튼을 누르는 순간 택배사 페이지에서 실시간으로 나온다.
  이 앱이 들고 있는 건 **이름 → 운송장번호** 연결뿐이다.

---

## 로그인과 주소

고객 실명·연락처 뒤 4자리·주소를 검색하는 화면이라 로그인 없이는 아무것도 열리지 않는다.
비밀번호는 하나다(초기값 `2026`). 한 번 로그인하면 30일 유지된다.

**매장과 물류팀은 계정이 아니라 주소로 나눈다:**

| 누구 | 받을 주소 | 하는 일 |
|---|---|---|
| 매장 매니저 | `https://<배포주소>/` | 고객 이름으로 배송 조회 |
| 물류팀 | `https://<배포주소>/upload` | 출고내역 엑셀 업로드 + 등록 이력 확인 |

로그인하면 원래 가려던 주소로 돌아간다. 각자 받은 주소를 즐겨찾기해두면 된다.
조회 화면에는 업로드 메뉴를 두지 않았다 — 매장에서 궁금해서 눌러보다 파일을 올리는 걸 막기 위해서다.

### 비밀번호 바꾸기

Vercel 대시보드 → 프로젝트 → **Settings → Environment Variables** 에서
`APP_PASSWORD` 값을 바꾸고 **재배포**하면 된다. 코드 수정은 필요 없다.
이미 로그인한 사람의 세션은 유지된다 — 전원 강제 로그아웃이 필요하면 `AUTH_SECRET` 도 새 값으로 바꾼다.

## 배포 (Vercel)

1. 이 저장소를 Vercel 프로젝트로 가져온다 (Framework: Next.js, 설정 변경 불필요).
2. **Environment Variables** 에 아래 5개를 넣는다.

   | 이름 | 값 |
   |---|---|
   | `MONGODB_URI` | yogico 공유 클러스터 주소 (vercelData 와 같은 값) |
   | `MONGODB_DB` | `cdapi` |
   | `RETENTION_DAYS` | `60` |
   | `APP_PASSWORD` | `2026` |
   | `AUTH_SECRET` | 무작위 문자열 32자 이상 — **반드시 새로 생성** (아래 명령) |

   ```bash
   node -e "console.log(require('crypto').randomBytes(32).toString('base64url'))"
   ```

   `AUTH_SECRET` 이 없으면 **로그인이 되지 않는다**(일부러 그렇게 했다 — 기본값으로 대체하면
   저장소를 본 사람 누구나 로그인 쿠키를 위조할 수 있다).

3. 배포. 리전은 `vercel.json` 에 서울(`icn1`)로 고정돼 있다.

MongoDB Atlas 의 접속 허용(Network Access)은 vercelData 가 이미 같은 클러스터를
Vercel 에서 쓰고 있으므로 따로 열 필요가 없다.

### Vercel 제약 — 알고 있을 것

- **업로드 파일은 4.5MB 가 상한**이다(Vercel 서버리스 요청 본문 제한, 설정으로 못 바꿈).
  물류팀 파일은 35일 누적이 약 0.5MB 라 여유가 충분하다. 업로드 화면이 4MB 를 넘으면 미리 막는다.
- 업로드 함수 실행 시간은 60초로 잡아뒀다(무료 플랜 상한). 3,600행 기준 5초 안팎이다.

## 화면

| 경로 | 쓰는 사람 | 하는 일 |
|---|---|---|
| `/login` | 전원 | 비밀번호 입력 |
| `/` | 매장 | 이름(2글자 이상) + 연락처 뒤 4자리로 조회 |
| `/upload` | 물류팀 | 출고내역 엑셀 업로드 + 등록 이력 확인 |

## 운영 규칙

**물류팀은 하루 한 번, 이카운트 게시판에 올리는 그 파일을 `/upload` 에도 올린다.**

- 파일은 가공하지 않아도 된다. 헤더를 이름으로 찾으므로 컬럼 순서가 달라도 읽는다.
  「운송장번호」와 「이름」 컬럼만 있으면 된다.
- 파일이 **누적본**(최근 약 35일치)이라 하루 빠져도 다음 날 파일이 채운다.
- 같은 운송장은 덮어쓰기라 다시 올려도 중복되지 않는다. 수정은 엑셀을 고쳐 다시 올리면 된다.
- 주말엔 배송이 없으므로 조회 화면의 신선도 배지는 **영업일 기준**으로 판단한다.
  금요일 업로드는 월요일 아침까지 정상으로 표시되고, 평일 하루를 빠뜨리면 경고가 뜬다.

### 보관 기간

업로드할 때마다 자동으로 정리된다(별도 스케줄러 없음).

- **출고된 건** — 출하 후 60일이 지나면 삭제.
- **미출고 건**(운송장 칸에 `재고소진`·`차량배차` 등이 적힌 건) — 물류팀 파일에 계속 실려 오는 동안은 보존,
  파일에서 빠진 지 60일이 지나면 삭제. 출하일로 자르면 정작 "언제 와요?" 문의가 오는 건이 사라지기 때문이다.

## 택배사 연동 — 알아둘 함정

코드는 `src/lib/carriers.ts` 한 곳에 모여 있다. URL 이 바뀌면 여기만 고치면 된다.

- **롯데는 틀린 운송장번호에도 에러를 내지 않고 "발송 준비중"을 띄운다.**
  그래서 링크를 만들기 전에 체크디지트(12자리, 앞 11자리 % 7 == 12번째)로 걸러낸다.
  실데이터 4,134건 중 4,131건 통과.
- **경동은 운송장번호를 따옴표 없이 JS 에 박는다.** 하이픈이 섞이면 산술식으로 계산돼
  **엉뚱한 남의 운송장이 조회된다.** 그래서 숫자만 남기는 정규화가 필수다.
- 운송장 칸에 `재고소진`·`차량배차`·`안전재고`·`직접수령` 같은 물류팀 메모가 들어온다.
  오류가 아니라 실제 상태이므로 화면에 그대로 보여준다.
- 경동 `www.` 주소는 http 로 강등되므로 `https://kdexp.com` 으로 고정한다.

src/app/api/upload/route.ts  업로드·적재·보관 정리 / 업로드 이력
src/app/api/shipments/route.ts  이름 검색 + 링크 생성
src/app/page.tsx             조회 화면
src/app/upload/page.tsx      업로드 + 등록 게시판
